# 当前线程与停止约定

设备模式使用独立摄像头线程和音频线程；文件模式使用一个线程交替交付实际存在的音视频轨。
每个 `MediaInput` 的打开、读取、解码、关闭与析构留在所属线程，其他线程只能调用 `requestStop()`。
预处理器、编码器及本地 MP4/M4A 写出器也在所属输入线程中串行使用。
这些线程的启动、停止和各处理模块的串接由 `pipeline/PublisherPipeline` 编排；
目录调整不改变原有线程、队列与停止行为。

开启 M07 后，`RtmpPublisher` 新增一个复用线程。所有 FLV 输出上下文和网络 I/O 只由此线程操作；
输入线程提交独占包与深复制编码参数。复用队列有容量限制，不能让网络故障造成无限积压，
也不能通过无限等待另一轨而堵住同时生产两轨的文件线程。
队列溢出后的恢复可能丢内容；存在视频时重新等待关键帧，音频跟随同一个恢复时间边界。

信号处理器只设置无锁停止标记，主线程轮询并通知输入/网络停止。
网络阻塞由 `AVIOInterruptCB` 的停止标记和截止时间中断。工作线程保存异常，由主线程统一报告；
上下文不在仍执行 FFmpeg I/O 的线程之外被并发释放。

EOF 的正常结束顺序：停止输入 → 排空重采样/FIFO → 排空编码器 → 标记各轨结束 →
在总计 `write_timeout_ms` 预算内排空复用队列、写尾并关闭网络 → 回收线程。
收尾阶段不再重连；超出预算会丢弃剩余网络包并记录日志。
Ctrl+C 立即中断网络等待、丢弃网络尾包；采集线程仍刷新编码器并尽力完成本地文件。
错误路径优先保证资源回收。具体接口与网络恢复约束见 [M07](rtmp-streaming.md)。

这只是当前采集并发与 M07 复用线程；M14 的采集、预处理、编码完整生产者/消费者流水线仍属后续工作。

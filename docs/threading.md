# 多线程流水线与缓冲队列

对应《方案.md》M14。线程编排位于两端 `pipeline`，通用队列位于
`common/queue/BoundedBlockingQueue.hpp`。入口及函数顺序见 [调用说明](function-call-order.md)。

## 队列与所有权

`BoundedBlockingQueue<T>` 使用互斥锁和读写条件变量，支持多生产者/消费者及可移动媒体对象。

| 操作 | 约定 |
|---|---|
| `push(T)` / `pop(T&)` | 满/空时等待；关闭后写失败并释放按值传入对象，但允许读到排空 |
| `tryPush` / `tryPop`、`pushFor` / `popFor` | 非阻塞或限时交接；写入失败保留调用者对象 |
| `tryPopIf` | 锁内检查队首；谓词不得重入队列或保留引用 |
| `close()` | 禁止写入、允许排空、唤醒所有等待者 |
| `abort()` | 关闭并丢弃缓存、唤醒等待者；媒体在锁外析构 |
| `clear()` | 清缓存但不关闭；不自动改变媒体代次 |
| `stats()` | 当前量、容量、峰值、入队/出队/丢弃数及关闭状态的一致快照 |

关闭/中止幂等，队列不能重新打开。销毁前必须停止并 join 全部使用者。
交接移动 `FramePtr`、`PacketPtr` 或拥有参数的事件，不借用上游临时指针。

## 主播端

```text
设备：视频采集 → 原始视频队列 → 视频预处理/H.264 ─┐
      音频采集 → 原始音频队列 → 音频预处理/AAC ──┤
文件：单输入线程解复用、解码后按轨分流             ↓
                                         输出事件队列
                                               ↓
                                    唯一本地封装/输出线程
                                      ├→ MP4 / M4A
                                      └→ RTMP 包队列 → 唯一 FLV/网络线程
```

每个 `MediaInput` 的打开、读取、解码和关闭在所属采集线程完成；其他线程只能请求停止。
文件模式共用一个输入线程。两路处理线程各自独占预处理器/编码器，输出线程独占本地封装上下文，
`RtmpPublisher` 独占 FLV 与网络 I/O。

输出事件顺序为 Start → 各轨参数 → 包 → End；Start 登记实际轨道，各轨 End 晚于编码尾包。
音频先协商编码器 PCM 格式/帧长。对应轨首次实际预处理输出后才创建文件；
本地保存与推流同时开启时创建独立 `AVPacket` 引用。

| 缓冲 | 默认限制 | 满/过期策略 |
|---|---|---|
| 原始视频 | 8 帧，实时年龄 200 ms | 实时满时丢最旧帧；消费时超龄且有后继帧则丢旧；非实时文件等待容量 |
| 原始音频 | 32 块 | 整块背压，保留 PCM 连续性 |
| 输出事件 | 两轨共 256 个 | 背压，不任意丢录制包 |
| RTMP 编码包 | 两轨共 256 包 | 严重积压整体恢复，等待视频关键帧并对齐音频 |

前三项由 `pipeline` 配置，RTMP 容量为 `output.queue_capacity`。
视频优先在编码前丢弃；压缩包不能随意删除单个 P/B 包。音频背压可传播到文件输入线程。
交接容量不是进程总内存上限，编解码器、FIFO、批次与纹理另占内存。

## 观众端

网络线程独占输入上下文；视频、音频工作线程分别独占解码器。
音频线程输出 F32 PCM 到有界 SPSC 环，SDL 回调只取已有样本，不等待视频、不写耗时日志。
CLI 主线程负责事件、同步、纹理和显示；GUI 通过后台协调线程调度、Qt 主线程绘制最新副本，
详见 [观众控制](player-control.md)。

| 缓冲 | 限制与策略 |
|---|---|
| `PacketBuffer` | 每轨 `input.queue_capacity`，两轨共用 `max_queue_bytes`/`max_buffer_ms`；管理 Reset/Packet/End、`serial` 与关键帧恢复 |
| `VideoFrameQueue` | 默认 3 帧、64 MiB；满时背压，等待中每 10 ms 检查代次；主调度循环另持有最多一帧 |
| PCM 环 | `audio.buffer_ms`，至少 4096 个每声道样本帧；满时只等待音频线程，停止可唤醒 |

主调度循环非阻塞取帧，按播放时钟丢迟到帧，阈值为
`min(sync.drop_threshold_ms, pipeline.max_video_age_ms)`；不按解码墙钟年龄删除未来帧。
外层策略锁到通用队列锁的方向固定。解码后丢帧不破坏解码参考链。
断线、严重积压和时间戳跳变统一递增 `serial`，撤销已出队旧媒体；恢复细节见 [网络可靠性](network-reliability.md)。

## 停止与异常

信号处理器只写无锁原子标志，协调层负责通知和回收；共享异常及复杂状态由互斥锁保护。

- 主播正常 EOF：关闭原始队列 → 排空预处理/编码 → 各轨 End → 最后一次 `finishTrack()` 关闭输出队列 →
  输出写本地尾部 → RTMP 在总计 `write_timeout_ms` 内排空/写尾 → join。禁用/缺失轨也结束。
- 主播主动停止：中断采集和网络 I/O、关闭原始队列，尽力排空本地录制；网络尾包可丢弃。
  工作线程异常则保存首错、abort 交接队列并中断其他阶段，join 后传播；线程创建失败也回收已启动线程。
- 观众先同时停止网络、视频、音频，再统一 join，最后释放 SDL 资源；
  仅禁用重连后的正常 EOF 排空解码尾部，主动停止/换代不播放旧尾帧。

音频回调 userdata 必须活到工作线程退出；持 stream 锁时不得反向获取 device 锁。
网络中断与退避可取消，不能用它中断永久卡住的本地磁盘 I/O；异常路径不保证文件完整。
统计单位与峰值见 [性能统计](performance-statistics.md)，构建见 [README](../README.md)。

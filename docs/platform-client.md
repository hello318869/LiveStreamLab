# 平台客户端（N04—N06）

无参数启动 `livestreamlab` 后，首页的“我要观看”和“我要开播”分别进入公开大厅与主播平台流程。
仍只有一个 `QApplication`；平台层只通过配置调用现有媒体 Session，不将 HTTP 或数据库引入采集、编码和播放核心。

## 配置与构建

程序优先读取可执行文件旁的 `config/platform.local.json`，没有本机覆盖文件时读取 `platform.json`；
默认文件由 CMake 部署，缺文件使用内置本机默认值。各设备应把自己的地址保存在 `platform.local.json`，
重新构建不会覆盖该文件，也不会把服务端本机配置复制到客户端。修改配置后重启客户端。

```json
{
  "api_base": "http://127.0.0.1:8090",
  "request_timeout_ms": 8000,
  "lobby_refresh_ms": 5000,
  "room_refresh_ms": 5000
}
```

API 地址使用 HTTP/HTTPS，不包含用户信息、查询串或片段；可包含反向代理路径前缀。
三个时间字段单位为毫秒，范围 1000–60000。未知字段和非法类型拒绝加载，配置不保存登录令牌或密码。
跨设备使用时，API 地址和服务端下发的媒体地址都必须是客户端可达地址；公网登录入口使用 HTTPS。

Windows 客户端依赖 Qt 6.5+ Widgets、Network，现有 Qt 6.8.3 SDK 可直接使用：

```powershell
cmake -S . -B build/cmake -DLSL_BUILD_TESTS=OFF
cmake --build build/cmake --config Release --target livestreamlab --parallel 4
```

后端按 [部署说明](platform-deployment.md) 配置数据库和 SRS。编译客户端不会自动执行 SQL、启动后端或重启 SRS。

## 大厅与观看

大厅允许匿名访问，卡片显示默认静态封面、房间标题、主播昵称、分类和状态，不为封面拉流。
支持分页、手动刷新、自动刷新、加载中、空列表和错误重试；隐藏大厅暂停刷新，同类请求不重叠。
媒体服务不可用时明确显示“直播状态暂不可确认”，不把缓存列表当成刚确认的在线结果。

每次选择主播重新获取 `/rooms/{room_id}/playback`，校验房间、场次和媒体服务状态后自动开始播放。
平台播放器隐藏地址输入，保留暂停、静音、音量、全屏与统计，返回按钮回到直播大厅。
播放器只查询当前房间，确认原场次终止、房间离线或切换场次后停止旧媒体和重连。
业务查询失败或主播 `RECONNECTING` 不触发结束；用户始终可以停止本地播放或返回大厅。

## 登录、房间与开播

主播流程提供注册、登录和退出；登录令牌仅存在应用内存，关闭应用后重新登录，密码不写配置。
登录后加载唯一个人房间，设置标题和固定枚举分类；采集设备、参数和预览复用原主播界面。
本地预览不创建直播会话。点击开播先提交房间设置、申请新会话，取得推流 URL 后才启动媒体。
等待服务器确认与本地推流状态分别展示，大厅是否出现由后端确认实际媒体进展决定。

同一次申请保留 `client_request_id`；HTTP 超时不证明服务端未创建会话。
已有会话或申请响应丢失时显示现有场次并提供明确操作，`409` 不自动结束其他客户端的直播。
服务端只发放一次推流凭证，查询已有场次不能恢复原地址；需由用户确认结束旧场次再重新申请。

N06 在应用内按用户保留请求 UUID、已知会话 ID 和下播意图，关闭工作窗口或同账号重新登录后继续核对。
记录不包含凭证，也不写磁盘。下播重试先查询匹配场次，每轮最多三次，再保留人工重试入口。
取消申请后尚无场次 ID、且房间确认离线时，可明确点击“核实并结束上次申请”，
提交原 UUID 来查明结果；若此前从未创建，可能新建准备会话后立即取消，全程不启动媒体。
新的正常开播操作必须等待该恢复意图收敛；不会把旧意图转移到其他客户端的场次。

停止、返回和关闭先请求本地媒体停止，同时尽力提交服务端下播；HTTP 失败不阻塞本地回收。
关闭时远端请求最多等待 `min(request_timeout_ms, 2000)` 毫秒，之后保留恢复记录并取消旧请求；
本地媒体仍须完成清理后才销毁窗口。正常应用退出走同样的回收路径，强制终止由后端时限兜底。
媒体启动失败时尽力取消准备场次；后端准备超时负责兜底。
后端确认 `STOPPING/ENDED/FAILED` 后停止本地推流重试，再次开播使用新场次。

## 请求与日志边界

所有业务请求使用 Qt 异步网络，不在界面线程同步等待。请求具有总超时、响应体上限、HTTP/JSON 检查，
拒绝自动跳转，不使用 Cookie；普通错误显示固定文案，不显示原始响应或网络错误中的 URL。
页面隐藏、退出或停止取消相关请求，回调检查生命周期及请求代次，迟到响应不能打开旧房间或启动已取消的媒体。
GET 网络失败或 HTTP 502/503/504 时最多重试一次，与首次请求共享总超时；
查询也可由定时刷新或用户重试恢复；开播、下播不盲目自动重提。

平台 UI 不显示或复制推流凭证。`--print-config` 隐藏输入/输出 URL 中的用户信息、查询和片段，
其输出用于诊断，含脱敏占位符的 URL 不能直接作为真实连接配置使用。
应用日志和 FFmpeg 完整诊断行在输出前隐藏媒体 URL、Bearer 及常见凭证字段，FFmpeg 过长诊断不输出原文。
SRS 和业务后端仍需各自按部署说明配置日志脱敏。

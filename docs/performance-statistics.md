# 性能统计

`common/stats/PerformanceStats.hpp` 定义快照，`CaptureTimestamp.*` 定义采集时间戳。
媒体线程更新所属数据，协调层采样，Qt 读取快照并报告绘制完成；UI 不直接操作媒体对象。
主播面板、观众摘要/详情和 CLI 日志共用以下口径。

## 速率、累计量与有效性

| 指标 | 计数点 |
|---|---|
| 采集 FPS | 成功读取的视频帧，进入原始队列前计数 |
| 编码 FPS | 编码器实际接受的视频帧，包含帧率整形重复画面 |
| 解码 FPS | 解码器输出的视频帧；不等于屏幕刷新率 |
| 发送/接收吞吐 | 成功提交/收到的编码音视频 payload 字节 × 8 / 秒 |

速率取单调时钟差值，至少积累 200 ms；GUI 正常约 200–300 ms 更新窗口，CLI 约每秒采样。
吞吐显示 kbps，不含封装/协议头或重传流量，不等于网卡线速；发送成功不证明远端收到。

新会话重置累计量与峰值，首个窗口前显示“—”。停止/失败后即时速率归零，
累计帧数/字节及峰值保留，队列深度取回收后状态。
音画误差与延迟各自判断有效性，不共用速率 `sampled` 标记。

## 队列与丢弃单位

| 队列 | 单位 |
|---|---|
| 主播原始视频/音频 | 视频帧 / 音频块 |
| 主播输出交接 | 参数、编码包、结束等混合事件 |
| RTMP 待发送 | 音视频压缩包共用容量，分轨显示当前量 |
| 观众视频/音频接收 | 各轨压缩包 |
| 观众解码视频 | 视频帧 |
| PCM 环 | 每声道样本帧，可换算毫秒 |

队列显示当前量、容量、会话峰值。PCM 时长仅含应用环，不含 SDL/硬件缓存。
各层容量与背压见 [线程说明](threading.md)，网络累计字段见 [网络可靠性](network-reliability.md)。

主播视频丢帧 = 原始队列丢旧/超龄/中止清理 + 预处理明确丢弃的输入帧；
重复画面、未生成补帧槽不计丢帧。网络丢包、输出中止混合事件分别计数，不换算成帧。

观众视频丢帧合计解码器明确丢帧、帧队列丢弃、同步/换代撤销候选；
同步器与渲染接口不对同一次丢弃重复累加。压缩包丢弃另计，不假定一包一帧。
计数覆盖流水线，不能代表显示器所有未实际显示的画面；Qt 只保留最新帧。

## 音画误差

`syncErrorMs = 当前调度视频 PTS − 音频估计播放位置`，正值表示视频超前。
仅同代次、有效音频主时钟、近期视频调度样本且正在播放时显示。
暂停、欠载、外部时钟降级、单轨、停止或过期样本显示“—”。
音频位置依据媒体 PTS、SDL 缓存与设备周期估计，详见 [音画同步](av-sync.md)。

## 采集到显示估计

```text
设备视频输出帧 → Unix 微秒时间戳 side data → libx264 / NVENC UDU SEI
 → SRS/网络 → H.264 解码还原 → Qt 新帧首次 paintEvent 完成 → 时间差
```

设备帧在原始队列入队前调用 `av_gettime()` 打戳；预处理/缩放/帧引用与补帧传播属性，
补帧保留原画面采集时间。libx264 和 NVENC 设备路径启用 `udu_sei=1`。
CLI 在 `render()` 返回后采样，日志名为 `capture_to_backend_ms`。

载荷为 `AV_FRAME_DATA_SEI_UNREGISTERED`，UUID
`5a667bf2-439c-4e37-9f9a-23c8116ba401`；24 字节 = 16 字节 UUID + 8 字节大端正整数 Unix 微秒。
接收端遍历同类 side data 匹配 UUID，仅修改本 UUID 数据，不占用 x264 版本信息。
文件输入不打本次采集戳、默认关闭编码遥测，避免旧录像标记冒充实时采集。

估计覆盖应用排队、预处理、编码、网络/服务器、解码及绘制等待；
起点是应用拿到采集解码帧，终点是软件绘制完成，不含设备曝光/内部缓存、系统合成和物理显示。
**跨机依赖系统时钟同步，程序不抵消钟差。** 负差或超过 24 小时标为时钟异常/过期，不钳制为零。
Qt 同一帧重绘不重复采样；暂停、重连、清帧、停止或超过 5 秒无新绘制样本时失效。

外部流、文件转推、OpenH264 或服务端/转码器过滤 UUID 时不可测；只有音频也不可测。
源码实现不能证明实际服务器保留 SEI，真实链路结果需运行测量。
延迟配置及观察方法见 [延迟说明](latency.md)，构建见 [README](../README.md)。

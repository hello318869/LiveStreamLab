# M16.3 性能统计

两端复用线程安全的会话快照显示性能数据。主播端的“性能统计”位于右侧滚动区域，
观众端在播放控制下方显示一行摘要，点击“详情”可展开队列、丢弃计数和测量原因。
CLI 每秒输出 `performance` / 原有流水线日志，无需调试器。

## 速率和累计量

| 指标 | 来源与单位 |
|---|---|
| 视频采集 FPS | 成功读取的设备/文件视频帧，在进入原始视频队列前计数；与目标 FPS 无关 |
| 视频编码 FPS | 编码器实际接受的视频帧数差值 / 采样秒数；包含帧率整形产生的重复画面 |
| 视频解码 FPS | 解码器实际输出的视频帧数差值 / 采样秒数；不是 Qt 屏幕刷新率 |
| 发送吞吐 | RTMP 成功提交的编码音视频 payload 字节差值 × 8 / 秒 |
| 接收吞吐 | 解复用器收到的编码 payload 字节差值 × 8 / 秒 |

速率使用单调时钟，至少积累 200 ms，正常会话约每 200–300 ms 形成新速率窗口；
界面更快刷新时读取同一已完成窗口，不重复累加。CLI 约每秒采样。
发送/接收吞吐以 kbps 显示，不包含 FLV、RTMP、HTTP、TCP/IP 头部或重传流量，
不能等同于网卡线速。发送成功也不证明观众已接收。

新会话重置累计量与峰值。首个速率窗口前显示“—”，不会把未知数据伪装成零。
停止/失败后即时 FPS 和吞吐归零，累计帧数、字节数与队列峰值保留；
队列深度取关闭/回收后的状态。音画误差和延迟使用独立有效性，不与速率 `sampled` 混用。

## 队列积压与丢弃

| 主播队列 | 单位 |
|---|---|
| 原始视频 | 视频帧 |
| 原始音频 | 音频块 |
| 编码输出交接 | 参数、编码包及结束等混合事件 |
| RTMP 待发送 | 音视频压缩包，共用容量；两轨当前积压分别列出 |

| 观众队列 | 单位 |
|---|---|
| 视频/音频接收 | 各轨压缩包，各有容量限制 |
| 解码视频 | 已解码视频帧 |
| PCM 环 | 每声道样本帧，另按采样率换算为毫秒 |

所有队列都有当前量、容量及本次会话峰值。PCM 时长只表示应用环中的待播样本，
不包含 SDL 内部缓存、音频硬件缓冲，也不是端到端直播延迟。

主播累计视频丢帧为：原始视频队列丢旧/超龄及中止清理的帧数，加预处理器因帧率整形
而明确丢弃的输入帧数。重复画面、未生成的时间轴补帧槽不计为丢帧。
RTMP 网络丢包和输出队列中止丢弃的混合事件分别列出，不转换成视频帧数。

观众累计视频丢帧合计解码器明确丢弃的视频帧、解码帧队列丢弃及同步调度/换代撤销的候选帧。
同步器和渲染接口对同一次丢弃不会重复累加。接收缓冲和视频解码器丢弃的压缩包另列。
这些是可核对的流水线丢弃计数，不把一个压缩包假设为一帧，也不声称统计了操作系统合成器
或显示器上所有未实际发光的画面。Qt 以最新帧交接，不构建无限 UI 帧队列。

## 音画同步误差

误差为“当前调度视频 PTS − 音频估计播放位置”，以带正负号的毫秒显示。
正数表示视频超前，负数表示视频落后。它来自现有 M13 同步器，音频位置仍是基于
媒体时间戳、SDL 缓存和设备周期的估计，不是扬声器物理输出位置测量。

只有同一代次、有有效音频主时钟、最近存在有效视频调度样本且正在播放时才显示。
暂停、停止、音频欠载、外部时钟降级、只有单轨或已过期样本显示“—”，不会显示假零误差。

## 采集到显示的端到端估计

本阶段实现视频时间戳随流传递，不能用 PTS 或队列年龄替代这条测量链路：

1. 设备视频采集输出时调用 `av_gettime()`，记录 Unix 微秒；该点在原始帧入队之前。
2. 时间戳作为 `AV_FRAME_DATA_SEI_UNREGISTERED` 随预处理、缩放、帧引用和补帧传播。
   补帧保留被复制画面的原采集时间，不重新打戳。
3. 设备模式下的 libx264 启用 `udu_sei=1`，把自定义载荷写入 H.264。
4. 接收端原生 H.264 解码器还原 SEI；读取时遍历所有同类 side data，匹配本应用 UUID。
5. Qt 在每个新帧首次 `paintEvent` 绘制完成后计算差值；重复曝光/重绘不重复采样。
   CLI 在后端 `render()` 返回后计算；其日志使用 `capture_to_backend_ms` 区分软件端点。

载荷 UUID 为 `5a667bf2-439c-4e37-9f9a-23c8116ba401`；精确 24 字节，
前 16 字节 UUID 定义 v1 格式，后 8 字节为大端正整数 Unix 微秒。
只修改本 UUID 的数据，不借用 x264 自身的版本信息 SEI，不改动像素或其他 UUID。
文件输入不打本次采集戳，编码器默认关闭该遥测，避免录像残留标记冒充实时采集。

这条估计包含应用内排队、预处理、编码、服务器/网络传输、接收缓存、解码和 Qt 绘制等待，
起点是应用获得采集解码帧，终点是软件绘制完成；不包含此前的摄像头内部缓冲/曝光，
也不包含此后的系统合成、显示器扫描与物理发光延迟。

**跨机器使用依赖两端系统时钟同步。** 本程序没有测量或抵消两机钟差；正数结果仍可能包含钟差，
所以界面始终标为“估计”。负差值或超过 24 小时的时间戳标为“时钟异常/过期”，不会钳制成零。
普通外部流、文件转推流、OpenH264 输出或服务器/转码器过滤了本 UUID 时，显示不可测及原因。
只有音频不提供这条视频端到端估计。暂停、重连、清帧、停止及超过 5 秒无新绘制样本时失效。
未实际运行验证服务端是否保留 SEI，不能仅凭编译通过宣称真实链路测量已通过。

## 文件与构建边界

公共值类型位于 `src/common/stats/PerformanceStats.hpp`，时间戳载荷位于
`src/common/stats/CaptureTimestamp.*`。媒体线程只采集/更新所属数据，协调线程发布快照，
Qt 主线程读取快照及报告绘制完成，不跨线程访问编码器、解码器或媒体队列。
沿用现有 CMake 目标，无额外构建脚本，无测试目标或自动测试新增。

2026-10-27：通过 CMake 配置和 Windows Release 的 `publisher_gui`、`player_gui`、
`publisher`、`player` 编译/链接，Qt/SDL3/FFmpeg 运行依赖已部署，`LSL_BUILD_TESTS=OFF`。
静态审查核对采样、丢弃口径、有效状态和 SEI 属性传播；本轮按要求不运行测试、GUI、
真实采集或推拉流，真实服务器保留 SEI、时钟误差和显示表现尚未运行验收。
